# VibePay 모놀리식 기능 완성 작업 문서

## 1. 문서 목적

이 문서는 다른 AI 세션에서 VibePay의 모놀리식 기능을 먼저 완성하기 위한 작업 지시서다.

목표는 MSA 전환 학습 전에 아래 조건을 만족하는 `온전한 모놀리식 기준선`을 만드는 것이다.

- 핵심 커머스 기능이 동작한다.
- 주문/결제/취소/포인트 흐름이 재현된다.
- 이후 MSA 전환 학습에서 비교 대상으로 삼을 수 있다.

이 문서는 `기능 완성`을 위한 문서이고,
분산 시스템 학습 자체는 [msa-study-roadmap.md](/Users/parkh/Dev/git/Project/vibe-pay/docs/study/msa-study-roadmap.md)에서 별도로 진행한다.

## 2. 범위

대상 모듈:

- `api/`
- 필요 시 `fo/`는 최소 연결만 수행

우선 완성해야 할 도메인:

- Member
- Goods
- Basket
- Order
- Payment
- Point
- Claim

## 3. 완료 기준

아래가 동작하면 모놀리식 기준선이 준비된 것으로 본다.

1. 회원 로그인 또는 인증 흐름이 동작한다.
2. 상품 조회가 가능하다.
3. 장바구니 담기/조회/주문 전환이 가능하다.
4. 카드 결제 주문이 가능하다.
5. 카드 + 포인트 복합 결제가 가능하다.
6. 주문 취소 및 부분 취소 흐름이 가능하다.
7. 포인트 적립/사용/환불 이력이 맞게 반영된다.
8. 기본 테스트와 수동 재현 절차가 남아 있다.

## 4. 구현 원칙

- 현재는 `api/` 단일 모듈 모놀리식 구조를 유지한다.
- 서비스 분리, Kafka, Redis, Saga, Outbox는 이 단계에서 도입하지 않는다.
- 우선은 도메인 흐름이 맞게 동작하는 것이 핵심이다.
- 과도한 튜닝보다 올바른 도메인 상태 전이와 테스트 가능성을 우선한다.
- 다만 명백한 비정상 구현은 남기지 않는다.

최소한 정리할 것:

- 명백한 N+1
- 치명적인 슬로우 쿼리
- 기본 인덱스 누락
- 주문/결제/취소 상태 전이 불일치
- 포인트 이중 반영 가능성

## 6. 구현 우선순위

### 1단계. 도메인 및 DB 기준선 정리

- 현재 스키마와 엔티티 매핑 점검
- 누락 테이블/컬럼/인덱스 확인
- `docs/database/ddl.sql` 동기화 필요 여부 점검
- 상태값과 연관관계가 도메인 문서와 맞는지 확인

### 2단계. 상품/회원/장바구니 기본 흐름 완성

- 회원 인증
- 상품 목록/상세
- 장바구니 추가/조회/수정/삭제
- 주문 전환 전 장바구니 검증

### 3단계. 주문 생성 흐름 완성

- 주문 생성
- 주문 상세 저장
- 주문 시점 상품/가격/수량 검증
- 장바구니 `is_order = true` 반영

### 4단계. 결제 흐름 완성

- 결제 수단별 기본 처리 구조 정리
- 카드 단독 결제
- 카드 + 포인트 복합 결제
- `pay_base`, `pay_interface_log` 기록 정합성 확인

### 5단계. 포인트 흐름 완성

- 사용 가능 포인트 검증
- 주문 시 포인트 사용
- 주문 완료 후 포인트 적립
- 취소 시 포인트 복원 또는 환불

### 6단계. 취소/클레임 흐름 완성

- 전체 취소
- 부분 취소
- 카드/포인트 복합 취소
- 원주문 추적과 상태 반영

### 7단계. 테스트와 재현 절차 정리

- 서비스 레이어 단위 테스트 보강
- 핵심 시나리오 수동 테스트 절차 문서화
- 테스트 데이터 준비 방법 정리

## 7. 필수 테스트 시나리오

`docs/domain/test-case.md`를 기준으로 최소 아래는 모두 통과해야 한다.

- 상품 1개 카드 결제 -> 취소
- 상품 2개 카드 결제 -> 부분 취소 -> 잔여 취소
- 상품 1개 카드 + 포인트 결제 -> 취소
- 상품 2개 카드 + 포인트 결제 -> 부분 취소 -> 잔여 취소
- 카드 전체 취소 + 포인트 부분 취소 케이스
