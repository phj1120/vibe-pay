# VibePay 모놀리식 기준선 상태

## 1. 구현된 기능

- 회원 JWT 인증 기반 API 접근
- 상품 조회, 장바구니 추가/조회/수정/삭제
- 주문서 조회 및 주문번호 생성
- 카드 단독 결제 주문
- 카드 + 포인트 복합 결제 주문
- 주문 완료 조회, 주문 목록 조회
- 주문 전체 취소 및 부분 취소
- 카드/포인트 환불 금액 분배 처리
- 포인트 사용/복원 이력 적재
- `pay_base`, `pay_interface_log` 결제/취소 로그 적재

## 2. 이번 정리 범위

- 주문 생성 시 주문금액과 결제금액 합계 일치 검증 추가
- 카드 결제 승인정보 필수, 포인트 결제 승인정보 금지 검증 추가
- 동일 결제수단 중복 요청 방지
- 주문 취소 시 본인 주문만 취소 가능하도록 소유권 검증 추가
- 주문 취소 요청의 중복 타깃 방지

## 3. 남은 미구현 또는 임시 처리

- 주문 실패 후 카드 망취소는 호출 지점만 있고 실제 PG 연동은 TODO 상태
- 주문 완료 후 포인트 적립 정책은 아직 미구현
- 재고 차감/복원과 동시성 제어는 아직 단순화 상태
- 반품/교환 플로우는 기준선 범위 밖
- 수동 E2E는 로컬 PG 테스트 환경 전제

## 5. 수동 재현 절차

### 사전 준비

1. PostgreSQL 16 실행
2. `docs/database/ddl.sql` 기준 스키마 생성
3. 회원/상품/포인트 기초 데이터 적재
4. `api`, `fo` 실행

### 시나리오 A. 상품 1개 카드 결제 후 취소

1. 로그인
2. 상품 1개를 장바구니에 담는다
3. 장바구니에서 주문서로 이동한다
4. 포인트를 사용하지 않고 카드 결제를 완료한다
5. 주문 완료 화면과 주문 목록에서 주문번호를 확인한다
6. 마이페이지 주문 목록에서 해당 상품을 취소한다
7. `order_detail`, `pay_base`, `pay_interface_log` 반영을 확인한다

기대 결과:

- 원주문 `order_detail` 는 `ORDER`
- 취소건 `order_detail` 가 `ORDER_CANCEL` 로 추가
- 카드 결제 원건의 `cancelable_amount` 감소
- 취소 환불건 `pay_base` 추가

### 시나리오 B. 상품 2개 카드 결제 후 부분 취소

1. 서로 다른 주문순번 2개가 포함되도록 주문한다
2. 주문 목록에서 1개 상품만 선택 취소한다
3. 다시 주문 목록에서 남은 1개를 취소한다

기대 결과:

- 첫 취소는 부분 취소 금액만 반영
- 마지막 취소 시 잔액이 0원이 되어도 기존 부분 취소 이력 기준으로 정상 처리

### 시나리오 C. 카드 + 포인트 복합 결제 후 취소

1. 주문서에서 포인트를 입력해 카드 + 포인트로 결제한다
2. 주문 목록에서 1개 또는 전체 취소를 수행한다

기대 결과:

- 취소 금액은 `PAY002.displaySequence` 역순으로 환불 처리
- 카드 환불 후 남는 금액이 있으면 포인트 복원 수행
- `point_history` 에 취소 적립 이력 생성

## 6. 이후 MSA 전환 시 주의할 결합 지점

- 주문 생성이 결제 승인, 포인트 사용, 장바구니 전환을 단일 트랜잭션에서 직접 호출
- 취소가 결제 환불, 포인트 복원, 주문 상세 적재를 동기 호출로 처리
- PG 연동 상세가 서비스 내부 전략 구현에 직접 결합
- 포인트 사용/복원이 주문/클레임 서비스와 강하게 결합
- 읽기/쓰기 저장소 분리는 되어 있지만 도메인 경계는 아직 모놀리식 내부 호출 기준
